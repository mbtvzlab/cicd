## Summary of requirements (from Lab-1.md)

- At least **7 classes**, 4 of which must be **complex** (5+ properties)
- At least one **enum**
- At least one **DateTime** property
- Correct **1-N and N-N** relationships

- Meaningful **LINQ queries** over the model

---

## Proposed object model

Your suggested core — `User`, `Project`, `Pipeline`, `RunLog` — is solid. Here are three additional classes to round it out to 7:

### Additional classes

| Class | Role |
|---|---|
| `PipelineStep` | A single step/stage within a Pipeline (e.g. "build", "test", "deploy"). A Pipeline has many Steps. |
| `Artifact` | A file produced by a RunLog (e.g. a build output, test report). A RunLog has many Artifacts. |
| `Trigger` | What caused a pipeline run — e.g. a git push, a schedule, or a manual trigger. Belongs to a RunLog. Could be a simple class or enum. |

---

## Full class structure

```
User
  - Id, Username, Email, PasswordHash, CreatedAt (DateTime), Role (enum: Admin/Developer/Viewer)
  - Projects (N-N via ProjectMember)

Project
  - Id, Name, Description, RepositoryUrl, CreatedAt (DateTime), IsActive
  - Owner (User, N-1)
  - Pipelines (1-N)
  - Members (N-N with User)

Pipeline
  - Id, Name, Description, CreatedAt (DateTime), IsEnabled, Branch
  - Project (N-1)
  - Steps (1-N → PipelineStep)
  - RunLogs (1-N)

PipelineStep
  - Id, Name, Command, Order (int), TimeoutSeconds, ContinueOnError
  - Pipeline (N-1)

RunLog
  - Id, StartedAt (DateTime), FinishedAt (DateTime?), Status (enum: Pending/Running/Success/Failed/Cancelled)
  - TriggeredBy (User, N-1)
  - TriggerType (enum: Manual/Push/Schedule/PullRequest)
  - Pipeline (N-1)
  - Artifacts (1-N)

Artifact
  - Id, FileName, FilePath, SizeBytes, CreatedAt (DateTime)
  - RunLog (N-1)

(ProjectMember — join table for N-N)
  - User, Project, Role (enum: Owner/Contributor/Viewer), JoinedAt (DateTime)
```

---

## Enums

- `UserRole` — Admin, Developer, Viewer
- `RunStatus` — Pending, Running, Success, Failed, Cancelled
- `TriggerType` — Manual, Push, Schedule, PullRequest
- `MemberRole` — Owner, Contributor, Viewer

---

## Notes / tradeoffs

- `ProjectMember` acts as the N-N join between `User` and `Project`. It can be a full class (with `JoinedAt`, `MemberRole`) or kept minimal — your call.
- `PipelineStep` vs. embedding steps as a list of strings: having a proper class makes LINQ queries more interesting (e.g. "find all pipelines with a step that times out under 30s").
- `Trigger` as a separate class vs. just an enum on `RunLog`: keeping it as fields on `RunLog` (TriggerType + TriggeredBy) is simpler and sufficient here.
- `Artifact` is optional if you want to stay minimal, but it gives a natural 1-N from `RunLog` and makes LINQ queries richer.

---

Does this structure work for you, or would you like to swap/simplify any of these classes before I start implementing?
